# GAME_DESIGN.md — "Клумба: цветочная головоломка"

Short name: **"Клумба"**. Working title "Garden" in code/repo. A browser logic puzzle game for Yandex Games.

## Theme

A cozy garden. Each colored region of the grid is a flower bed; the player plants exactly one flower per bed. Mascot: a small ladybug who gives hints (placeholder, drawn with SVG for now).

## Rules

An N×N grid is divided into N colored regions ("flower beds"). The player places flowers so that:

- each region contains exactly one flower;
- each row contains exactly one flower;
- each column contains exactly one flower;
- flowers never touch each other, not even diagonally (no two flowers in adjacent cells, including diagonal neighbors).

## Controls

- Single tap on an empty cell → white X mark ("no flower here"), placed immediately, no delay.
- Double tap (a second tap within ~300 ms on the same cell, while it shows an X) → the X becomes a flower.
- Single tap on an X with no quick follow-up → clears back to empty.
- The pre-placed flower, any correctly planted flower, and any red X marks all lock immediately and can't be changed — tapping or dragging over them does nothing.

A flower always needs a deliberate double tap; a single tap never plants one directly. Works the same with mouse and touch, and `touch-action: none` on the board plus a non-zoomable viewport keep a fast double-tap from triggering the browser's zoom gesture, and keep the page from scrolling while dragging on the board.

**Drag to mark.** Press and drag across cells to mark or clear several at once: if the drag starts on an empty cell, every empty cell it passes gets a white X; if it starts on a white X, every white X it passes is cleared. Flowers, the pre-placed flower, and red X marks are never touched by a drag — the drag just passes over them. A drag never triggers the double-tap flower placement, regardless of how it moves.

## Starting flower

At the start of every level, one flower from the solution is already planted and locked — the player always has a confirmed starting point and can't change or remove it.

## Mistake feedback

If the player plants a flower in a cell that breaks a rule or isn't part of the level's one true solution, that cell gets a red X (visually distinct from the plain white "no flower" X) with a short shake, one water drop pops/fades away, and the cell locks — the red X stays as a permanent marker that no flower belongs there.

## Level-complete fill

The instant the last correct flower is planted, every remaining empty cell on the board gets a white X in a quick staggered wave (each cell appearing ~35ms after the last), and only once that wave finishes does the win screen appear. A solved board is never left with ambiguous empty cells.

## Level generator

1. Place N flowers on an N×N grid satisfying all rules (one per row/column, no touching).
2. Grow colored regions outward from each flower to partition the grid into N connected regions.
3. Run a solver against the generated puzzle (regions only, flower positions hidden) to verify the solution is unique.
4. If not unique, regenerate.

Grid size by level: 1-2 → 4×4, 3-5 → 5×5, 6-9 → 6×6, 10-14 → 7×7, 15+ → 8×8 (the cap). Every level has exactly one pre-placed, locked flower regardless of size.

8×8 generation is verified fast: across levels 15-74 the slowest observed build was ~74ms, far under the 1-second budget, so no precomputation/caching was needed. `tests/progression-speed.test.js` guards this (fails if any 8×8 build in a 60-level sample takes ≥1000ms) and also locks in the exact size-per-level table above.

**Deterministic by level.** Every random choice in generation (flower placement, region growth, which solution flower is pre-placed) is drawn from a seeded PRNG (`js/rng.js`, mulberry32) seeded by the level number itself — never `Math.random`. Level N therefore looks exactly the same — same beds, same colors, same pre-placed flower — for every player, every time, every reload. `tests/determinism.test.js` builds each of a sample of levels twice and asserts the results are identical.

## Saving in-progress play

The current board (every cell's X/flower/red-X mark and lock state), remaining water drops, and the level's running score are saved to localStorage after every move, keyed by level number. Reloading mid-level restores exactly where the player left off. The saved board is cleared when the level is completed (solved) or explicitly restarted (Retry); a level never resumes stale progress after either of those.

## Rules bar

Above the board, three small cards each show a tiny 3×3 diagram (CSS/SVG) next to a short rule reminder, all text through i18n:

- **"1 flower per bed"** — a flower in the center cell; the top row and left column cells (same bed color) show X; the remaining cells are neutral.
- **"1 flower per row and column"** — a flower in the top-middle cell; X on the other two top-row cells and on the two cells below it in the middle column; the rest neutral.
- **"Flowers can't touch"** — a flower in the center cell; X on all 8 surrounding cells.

On levels 1-5 (inline mode) the bar's horizontal padding matches the board's own side padding, and the three cards share that width equally (`flex: 1 1 0; min-width: 0`) rather than each claiming a fixed width, so the row can never grow wider than the viewport — the rule text wraps onto a second line instead, while the mini 3×3 diagrams stay full-size. The level-6+ popup mode is unaffected.

## Bed tracker

A row above the board shows one small icon per flower bed, colored to match that bed, in a fixed left-to-right order (by bed index). Once a bed has its correct flower, its icon shows a small flower; otherwise it stays a plain colored swatch.

## Feedback and scoring

- Planting a flower correctly earns 10 points: a floating "+10" pops up near that cell and fades out, and the score display updates immediately. The cell locks the instant it's correct (see Controls above), so it can never be re-earned within the same attempt — and as a belt-and-suspenders safeguard, each cell's points are tracked as "awarded" in the saved board state too, so even a hypothetical future bug that unlocked a cell couldn't double-award it.
- Score is tracked two ways: the current level's score (resets each attempt, saved/restored with the board so a reload mid-level doesn't lose it), and the running total across the whole game. The total only ever gains a level's points once — on that level's first-ever completion — so retrying or somehow replaying an already-completed level never inflates it (best time and star rating can still improve on a replay, just not the total score). While playing, the displayed total previews the current level's in-progress score on top of the real banked total; once won, it shows the real banked total exactly.
- Finishing a level with no mistakes shows a big animated "Perfect!"; finishing after at least one mistake shows "Done!" instead — either way the level's score earned is shown alongside it.

## Win screen rating

No fake "you beat N% of players" claims anywhere — that kind of stat only appears once it can be real (see Roadmap step 8). Instead, the win screen shows:

- **1-3 stars**, computed from mistakes made and time taken this level: 3 stars needs zero mistakes and finishing within `gridSize × 10` seconds; 2 stars needs at most one mistake and finishing within `gridSize × 20` seconds; otherwise 1 star. Stars pop in with a short staggered animation.
- **A rank title** tied 1:1 to the star count: 1 star → "Gardener" ("Садовник"), 2 stars → "Skilled gardener" ("Умелый садовник"), 3 stars → "Master gardener" ("Мастер-садовник").
- **Best time for the level**, persisted per level in localStorage and updated whenever a run beats it.
- **The seeds earned this win** ("+N" next to the stars, with a short pop animation honoring Reduce Motion) - only on a level's first-ever completion (see Soft currency: seeds below); a replay shows nothing here rather than a stale or zero number.

## Lives

- 3 lives per level, shown as water drops (💧-style, drawn in SVG) instead of hearts.
- A life (water drop) is lost when a flower is placed in a cell that breaks a rule or isn't part of the unique solution (see Mistake feedback above).

## Soft currency: seeds

- **Starting balance:** 30 seeds, granted exactly once, the very first time `platform.loadSeeds()` is ever called with nothing in storage yet - that grant is persisted immediately, so a balance that later drops to 0 (from spending) is never mistaken for "never granted" and re-topped-up. A stored value that fails to parse is treated as corrupted and defaults to 0, not a fresh grant.
- **Earning:** seeds are earned on a level's *first-ever* completion, by star rating: 1 star → 3 seeds, 2 stars → 5 seeds, 3 stars → 8 seeds (`SEED_REWARD_BY_RATING` in `js/state.js`, the one place these values live). This reuses the exact same `loadBestTime`/`saveBestTime` "already completed" signal that already guards the total score (see Feedback and scoring above), so retrying or replaying an already-completed level never farms extra seeds - verified by `tests/hints-seeds.test.js` the same way `tests/score-exploit.test.js` verifies it for score. Seeds are also earned through the daily check-in (see below).
- **Spending:** the only sink right now is hints (see Hints below). Seeds are completely independent of score points - there is no conversion either way, and a hint never earns or costs any score points.
- **Display:** a small seed-icon pill in the game's top bar and on the main menu, always showing the real live balance - never a fake or hardcoded number.

## Hints

- A ladybug-mascot button near the board (reusing the same ladybug SVG used elsewhere) shows its cost - 10 seeds (`HINT_COST` in `js/state.js`) - directly on the button. One tap spends it immediately, no confirmation dialog.
- **Effect:** plants one correct flower from the level's unique solution. The target is chosen deterministically: among the solution's flowers not yet planted, the one with the lowest row index (the solution list is already ordered ascending by row by construction - see `buildLevel`/`generator.js` - so a hint is a plain forward scan for the first cell that isn't already a flower; a defensive skip for a red-X state is included even though a solution cell can never actually be marked wrong in normal play). If that cell currently holds a white X, the hint simply overwrites it with the flower.
- **Behaves exactly like a correctly planted flower:** same lock, same bloom animation (a plain fade instead, under Reduce Motion), same bed-tracker update, and if it's the last flower, the same level-complete wave fill and win flow trigger.
- **Scoring is untouched:** a hint earns no points (never the +10), costs no life, and is not a mistake - so it never changes "Perfect!" vs "Done!" (mistakes-only) or the star rating (mistakes + time only). The hinted cell is still added to the save's `awardedCells` set, exactly like a correct tap, as the same belt-and-suspenders guard against ever double-scoring it later - just with 0 points attached.
- **Cost and eligibility:** the cost is deducted and persisted *before* the cell even changes, so an interruption mid-animation can never leave a player charged-but-hintless. The button is disabled whenever the balance is below the cost, the level isn't currently in the "playing" state (solved, failed, or the win-fill wave still running), or no unplanted solution flower remains. There's no "watch an ad for seeds" stub here - that arrives with the Yandex SDK step.
- **No refunds:** Retry does not refund seeds already spent on hints this attempt - only `lives`/`levelScore`/the board reset, the seed balance is a separate, persistent value. A hinted cell is saved and restored across reloads exactly like any other locked flower.
- **Double-spend protection:** a short lock window (`HINT_LOCK_MS`, 400ms) after each successful hint rejects any immediately-repeated call, so a hint can never charge twice for the same flower even from a very fast repeated tap.
- Not available in the separate first-launch tutorial (which has no hint button in its markup at all - it's a fixed, hand-made board, never a real generated level).
- All text via i18n (ru + en); the hint button is ≥44px tall for touch.

## Daily check-in

- A 7-day streak row (`js/checkin.js`): one reward claimable per calendar day. "Today" is always the player's LOCAL calendar date, derived from local date parts (`getFullYear`/`getMonth`/`getDate`), never from a UTC view of the clock.
- **Rewards**, keyed by position in the 7-day cycle (`SEED_REWARD_BY_DAY` in `js/checkin.js`, the one place these values live): day 4 → 10 seeds, day 7 → 30 seeds, every other day (1, 2, 3, 5, 6) → 0 seeds, just marked claimed (a small flower, reusing `flowerSvgFor`) and keeps the streak going. Seeds are always credited through the same seeds module hints use (`platform.saveSeeds`/`loadSeeds`) - this file never writes the balance directly.
- **Streak rules:** claiming when the last claim date is already today is a no-op. If the last claim was exactly yesterday, the streak continues (+1); if it was earlier than yesterday (a missed day) or there's no previous claim, the streak resets to 1. Position in the row is `((currentStreak - 1) % 7) + 1`, so after day 7 the next consecutive day wraps to position 1 of a new cycle while `currentStreak` itself keeps counting (so `bestStreak` can exceed 7). `bestStreak = max(bestStreak, currentStreak)` on every claim and never decreases.
- **Day-diffing is DST-safe:** the gap between two calendar dates is computed from `Date.UTC(y, m, d)` anchors of the date *parts*, never by dividing a millisecond difference between real local `Date` objects - the latter can be off by an hour across a DST boundary (a local day can be 23 or 25 real hours long), while a pure calendar-date UTC anchor has no notion of time-of-day or DST at all.
- **Clock-tampering guard:** if today's date is *before* the last claim date (the device clock moved backwards), the claim grants nothing and the streak record is left completely untouched - the UI just shows the check-in as already claimed. This is only a sanity guard, not real fraud prevention: a purely client-side check can't stop someone from moving the clock forward one day at a time to farm streaks, only catch an actual backwards jump. A real fix needs server time, which is a roadmap step 8 follow-up once the Yandex SDK is wired in.
- **Persist-before-credit:** a claim writes the new streak record to storage *first*, then credits seeds - so a reload or crash between the two steps can never produce a double claim (a later attempt always finds `lastClaimDate` already equal to today), though in that narrow window the reward itself could be lost rather than duplicated, which is the intended trade-off.
- **Testability:** all date logic flows through a single injectable clock, `platform.now()` (defaults to `new Date()`), so tests simulate arbitrary sequences of days without waiting for real ones; `platform.saveCheckin`/`loadCheckin` store the record with corruption-tolerant loading (missing, unparsable, or wrong-shaped data falls back to a fresh `{ lastClaimDate: null, currentStreak: 0, bestStreak: 0 }` instead of throwing or trusting bad data).
- **UI:** a "Ежедневная награда" button on the main menu (after Settings, before the daily-challenge lock teaser) shows a small dot badge while today's reward is unclaimed - no auto-opening popup, the badge is the only nudge. It opens a popup (same overlay/"night garden" tokens as Settings) with the 7-day row (each cell a day number, or a flower once claimed; today's cell gets a highlight ring; future days are dimmed; days 4 and 7 show their seed reward next to the seed icon), the current and best streak labelled clearly, and a "Забрать" button that disables to "Награда получена" immediately after claiming. Claiming pops a short "+N" seed animation when a day actually pays out (honoring Reduce Motion - no pop on a 0-reward day), and the menu's seed pill updates immediately. Not shown on the loading screen or inside a level.

## Flower collection

- Different flower types unlock as the player progresses through levels.
- The game starts with one flower type; more are added and become plantable as levels advance.

## Accessibility

- Every flower bed region must be distinguishable not only by color but also by a subtle pattern (dots, stripes, etc.) drawn in SVG/CSS.
- A settings toggle lets the player turn region patterns on/off — **off by default** (patterns are an accessibility aid, not the normal look).
- A "Reduce motion" setting disables ambient particles and the longer decorative animations (bloom overshoot, pollen sparkles, win-screen sway), and is also honored automatically from the OS-level `prefers-reduced-motion: reduce` media query.
- A "Vibrate on mistake" setting (on by default) triggers a short `navigator.vibrate` pulse on a wrong placement, where supported. Support is feature-detected (`'vibrate' in navigator`), not assumed — browsers that implement it (e.g. Android Chrome) get the real pulse, while browsers that don't (e.g. iOS Safari, which has no `navigator.vibrate` at all) show the toggle disabled with a short explanatory note instead of silently doing nothing; the stored setting's value is unaffected either way.

## Loading screen, main menu, and navigation

- The game opens on a CSS/SVG-only loading screen (ladybug mascot, the title "Клумба", a three-dot pulse indicator) that hands off to `platform.gameReady()` once i18n, settings, and saves are ready - in practice that's all synchronous today, so the screen leaves almost immediately with a short ~300ms fade and never delays the first frame; a 5s hang-protection timeout forces the same transition on its own if a future async init step (e.g. the real Yandex SDK in step 8) ever stalls. A small router (`js/router.js`) handles the switch between three sibling screens - loading, menu, game - by toggling `hidden`, no frameworks or build step involved.
- The main menu (`js/menu.js`) shows the title, subtitle, mascot, and three buttons: "Играть" / "Продолжить · Уровень N", "Как играть", and "Настройки" - the latter two just call the existing tutorial and settings popup rather than duplicating their logic. The Play button reads "Продолжить · Уровень N" only once the saved board for the current level actually holds a player move beyond the pre-placed starting flower (an X, a red X, or a flower the player planted - detected via the existing `awardedCells` safeguard, since the pre-placed flower itself is never added there); with no save, an empty board, or only the starting flower, it reads plain "Играть". Either way, pressing it runs the tutorial first on first launch (while it isn't completed yet) and enters the game right after; once the tutorial is done, it goes straight to the game. A fourth button is a disabled, non-interactive daily-challenge teaser (lock icon + "Откроется на уровне 15") that hides itself from level 15 onward, so the menu never promises a feature that doesn't exist yet (that's roadmap step 7).
- The back button now performs a real transition back to the menu, replacing the old `platform.navigateToMenu` stub (screen navigation isn't a platform/SDK concern, so it no longer lives in `platform.js`). The game's state is never torn down when leaving it, so the board, lives, and score are exactly where the player left them both on returning to the menu and on pressing "Продолжить" afterward - including across a page reload, since they were already being saved to localStorage.

## Themes

- **Registry (`js/themes.js`).** Two themes, keyed by id: `winter` and `garden`. Each one provides a token map (CSS custom-property overrides), an ordered list of 8 bed colors, a piece-art SVG component, a mascot/hint-icon/currency-icon set, and i18n keys for the text that differs. A theme is purely visual - it never touches the RNG, generator, solver, or state: level N always has the exact same beds and solution under either theme, only drawn differently (`tests/themes.test.js` guards this directly).
- **Default.** `DEFAULT_THEME_ID = 'winter'` is the one constant that picks the default; changing it to `'garden'` is the only change needed to make garden the default again. The chosen theme is persisted via `platform.saveTheme`/`loadTheme` (corruption-tolerant - an invalid or missing stored value resolves to `DEFAULT_THEME_ID` in `Themes.applyTheme`, not in `platform.js`, since the registry is the one place that knows which ids are valid).
- **Applying a theme.** `Themes.applyTheme(id)` sets `data-theme` on `<html>` and writes the theme's token overrides as inline CSS custom properties on the root element (clearing any previous theme's overrides first). The `:root` block in `css/style.css` is left exactly as the original dark "night garden" look - that's what the garden theme's (empty) token map relies on, which is what keeps "garden theme: exactly today's look" true for free. `render.js`'s `setTheme()` wraps this together with switching the i18n piece-name axis (`I18n.setTheme`) and refreshing everything already drawn with theme-baked content: rule/tutorial text, bed-tracker icons, any already-planted piece SVGs, the mascot in all its slots (loading/menu/tutorial), the hint button's icon, and every currency-icon slot (bed *background* colors update for free via the CSS variables, with no explicit refresh needed).
- **Winter theme (light).** A warm cream-to-pale-pink background gradient (no pure white anywhere - off-white/cream tokens throughout) with slow falling snow motes (the same ambient-particle system as garden's pollen, just falling instead of rising, still honoring Reduce motion), a snow drift along the bottom edge and two small snowy fir trees in the lower corners (plain CSS/SVG, `pointer-events: none`, purely decorative); all of it hides automatically in landscape or on a short viewport (`@media (max-height: 700px), (orientation: landscape)`) so it can never shrink the board or overlap controls. A thin candy-cane rim (diagonal red/off-white `repeating-linear-gradient`) frames the board; tiles get a lighter "icy-candy" bevel (brighter highlight, cool blue-grey lower edge, a translucent sheen) on the same geometry/press behavior as today. 8 medium-saturation candy bed colors (mint, strawberry, lemon, grape, blueberry, orange sherbet, lime, bubblegum) were tuned - and are guarded by `tests/themes.test.js` - to stay clearly distinguishable from each other and from the light background. The piece is a gingerbread person with a **fixed** warm-brown body and cream icing outline/bow/buttons/smile (not hue-derived like the flower, since a fixed palette is simpler to guarantee legible on every bed color including yellow and orange - also guarded by `tests/themes.test.js`'s contrast-ratio check). The ladybug mascot wears a small Santa hat overlay (loading screen, menu, tutorial bubble); the hint button shows a candy-cane icon instead of the ladybug; the currency ("семена"/seeds" - the name is unchanged) icon becomes a snowflake everywhere it appears. Several tokens were deliberately decoupled from `--pollen-color` (`--particle-glow`, `--currency-icon-color`, `--result-perfect-color`, `--star-filled-fill`/`--star-filled-stroke`) so a near-white snow-mote color doesn't also get reused somewhere it would vanish against a light panel (the currency icon, the "Perfect!" text, the check-in notification dot, the win-screen stars) - garden's tokens still point straight at the old values, so it looks exactly as before. Rule/tutorial text names the piece "пряник"/"gingerbread".
- **Garden theme (dark).** Exactly today's "night garden" look and piece art (the "rose spiral" flower, the plain ladybug, the leaf/seed-drop currency icon) - unchanged.
- **Settings.** A "Тема" row in the settings popup offers "Зима"/"Winter" and "Сад"/"Garden" as two small pill buttons (reusing the panel/accent tokens the rest of the settings UI uses). Switching applies immediately, no reload, and persists.

## Visual style

- **Theme.** Two selectable themes - see the Themes section above for winter (light, default) vs. garden (dark, "night garden", today's original look). Everything below describes the garden theme's tokens/values specifically, which are also the `:root` defaults in `css/style.css`; a dark-green gradient background (no pure white or pure black anywhere in the palette). All colors, radii, shadows, and animation durations/easings are design tokens (CSS custom properties) defined once in `:root`, so the look can be re-themed from one place - which is exactly how the winter theme overrides a subset of them.
- **Bed colors:** 8 muted pastel tones (`--region-0`..`--region-7`), chosen to stay clearly distinguishable from each other against the dark background.
- **Tiles ("candy tile" look):** one uniform gap between every cell — ~6-8px on small boards, scaled down on bigger ones but never below ~3px (`gapForSize()` in `js/render.js`: 8px at size ≤4, 7px at 5, 6px at 6, 4.5px at 7, 3px at 8) — identical whether two neighboring cells share a bed or not; beds are told apart only by color (plus the optional pattern toggle). Cells use a large `border-radius: 24%` (scales automatically with cell size) for a soft, chunky look, plus more volume than a flat tile: a soft lighter top highlight, a ~3px darker lower edge, and a gentle drop shadow (`--tile-highlight`/`--tile-edge`/`--tile-shadow`) — still calm, no harsh contrast. Pressing/dragging a cell reduces that lower edge and shifts the tile down by the matching `--tile-press-shift`, then springs back. Verified an 8×8 board keeps ~44px cells on a 390×844 phone-portrait viewport, comfortably over the 36px minimum tap target.
- **Flowers:** a single reusable "rose spiral" SVG component (`flowerSvgFor(region)` in `js/render.js`) — three rings of pointed petals (6 outer, 5 middle, 4 inner), each ring rotated a bit further than the last, opening outer-to-inner with a small scale+rotate overshoot ("spiral unfurl"). On the board it fills ~78% of its cell (`.cell-mark`) so it reads at a glance even on an 8×8 board; the per-bed tracker icon and win-screen bloom follow the same ~75-78% fill convention at their own sizes. The flower's color is *generated from its bed's own hue* at draw time (`flowerPalette()`: same hue, pushed at least ~40 lightness points lighter or darker — whichever increases contrast against the bed's own lightness — and nudged a little further ring by ring, each stage independently clamped so no ring can ever collapse to pure black/white), not a separate hardcoded palette, so any new bed color automatically gets a flower that contrasts with it. The exact same component renders the flower everywhere one appears: the board, the per-bed tracker row, the tutorial, and a small decorative bloom on the win screen. Once the level is solved, every flower on the board still sways gently in place. X marks use a single dark-ink tone (`--mark-ink`) chosen to stay readable on every bed color; a red disc + bold X (`--mark-wrong`) marks a mistake.
- **Cell feel:** pressing a cell "sinks" it (see Tiles above) and springs back with a slight overshoot; dragging to mark a run of cells sinks each cell in turn as the pointer passes over it; X marks pop in with a short scale animation.
- No fake "fastest player"/leaderboard-percentage banners anywhere on the board or win screen (see Win screen rating below — that rule still holds).
- **Top bar:** back button (left, returns to the main menu) and a settings button (right) frame a centered stack of pills — level number, then score (small leaf icon), then the seed balance (small seed icon) — plus three glowing water-drop lives next to the settings button; a lost drop fades and pops exactly as before. The same seed pill also appears on the main menu.
- **Rules bar:** the three rule cards show inline on levels 1-5; from level 6 on they collapse behind a small "?" button that opens them in a dismissible popup instead, keeping the board bigger on larger levels.
- **Hint row:** a single pill-shaped button above the board (ladybug mascot icon, "Hint" label, and its seed cost) - disabled whenever a hint isn't currently usable (see Hints above).
- **Settings popup:** patterns, reduce motion, and vibration toggles plus a "Replay tutorial" button, opened from the top-bar settings button.
- **Tutorial:** the dimming/backdrop uses the same dark-green scrim as the rest of the UI; the one interactive cell gets a soft glowing ring instead of a hard highlight; hints are shown in a speech bubble anchored to a small ladybug mascot (SVG) rather than a bare box.
- **Ambient particles:** a handful of slow-drifting pollen/firefly motes rendered as small glowing dots behind the UI (plain CSS animation on ~10 tiny absolutely-positioned elements — no canvas, no blur over large areas, so it stays cheap on weak phones). Disabled entirely under "Reduce motion" or `prefers-reduced-motion`.
- Calm, cozy tone — not stressful despite the lives mechanic.
- CSS/SVG graphics only; no image/bitmap assets.

## Roadmap

1. **Core**: grid, rules check, generator with uniqueness check, lives, win screen, next level, level number saved in localStorage.

4. Hints and soft currency.
